Overview

What this repository is

Claude Code does not currently expose a public “install third-party plugin from repo” flow like an app store. This repo ships a bridge runtime, a one-command Claude Code installer, and ready-to-copy config examples—plugin-like UX with Claude Code configuration as the integration point.

Built for

  • Claude Code users routing through a Codex-backed subscription
  • Operators wanting a documented compatibility surface
  • Developers wanting an inspectable starting point instead of a closed relay

What it is not

  • Not a full hosted service
  • Not a secret production config dump
  • Not an official Claude Code marketplace plugin

In one sentence: You keep using Claude Code as usual; requests go through a Codex-backed bridge you configure.

Install

Fastest path: install into Claude Code

Terminal
curl -fsSL https://raw.githubusercontent.com/UnstoppableCurry/cc-codex-plugin/main/scripts/install-claude-code.sh | bash

The installer will:

  • Ask for your bridge base URL
  • Ask for your gateway key
  • Optionally set a default model (claude-sonnet-4-6 if left blank)
  • Update ~/.claude/settings.json, merging only required env keys

Configured keys: ANTHROPIC_AUTH_TOKEN, ANTHROPIC_BASE_URL, ANTHROPIC_MODEL. Restart Claude Code after install.

Manual install

Copy from examples/claude-code/settings.json into ~/.claude/settings.json. Uninstall with scripts/uninstall-claude-code.sh.

Workflow

Recommended validation flow

The intended main path for end users is the installer above. Full bridge deployment is in Self-host and repo docs.

1. Start the bridge

  1. Copy config.example.toml to config.toml
  2. Fill in auth token and upstream values you control
  3. Build and run the Docker image

2. Connect Claude Code

Installer or manual example sets ANTHROPIC_AUTH_TOKEN, ANTHROPIC_BASE_URL, ANTHROPIC_MODEL.

3. Connect Codex (optional)

Use examples/codex/config.example.toml and point Codex at the local bridge provider.

4. Validate

Start with a plain single-agent prompt:

  • Ask a simple question
  • Ask for a small code explanation
  • Confirm request logs hit the bridge

Only after that, test tools or multi-step workflows.

Limitations

Request compatibility is not environment compatibility

The bridge can normalize request/response formats. It cannot grant local IDE or CLI capabilities the client expects from its own machine.

Claude Code subagents depend on the local machine

If Claude Code tries to create isolated subagents, the client may require:

  • A valid Git repository
  • At least one commit
  • Working git worktree support
  • Or configured WorktreeCreate / WorktreeRemove hooks

If local prerequisites are missing, no bridge can fully fix that from the server side alone.

Recommended operating mode

  • Use the bridge to stabilize normal Claude Code / Codex requests
  • Treat swarm or multi-agent workflows as a separate capability validated on the client machine

Self-host

Run the bridge yourself

Docker
cp config.example.toml config.toml docker build -t cc-codex-plugin . docker run --rm -p 8000:8000 \ -v "$(pwd)/config.toml:/app/config.toml:ro" \ cc-codex-plugin \ ccproxy serve --config /app/config.toml --host 0.0.0.0 --port 8000

Then point Claude Code with the installer or manual settings. Model mapping is explicit and documented—see model mapping.
